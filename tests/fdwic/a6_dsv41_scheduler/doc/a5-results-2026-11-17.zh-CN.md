# 单卡 SWA 的 A5／A6 性能对比

**两端都已通过独立 SWA 的固定输入和参考输出校验。PR 主指标是 L0 首末计算核的时间。A5 迁移起点复测为 269.698 µs，当前分支为 269.286 µs。A6 已返回一轮 L4，L0 性能和 L3 分解待填。**

用例是 DSv4.1 的 SWA 注意力子层，走生产 HBG AICore 调度。两端使用同一份输入、参考和 16 个计算任务。19 个核按平台重新编译，A5 展开 578 个执行实例，A6 按 1C1V 分工展开 570 个，检查 30 个可写缓冲区。A5 为 Ascend950DT（32C、64V），A6 为 Ascend960DT（54C、54V）。跨代差值包含算子分片、硬件、运行时和 Host 环境差异。

## AICPU 前后段与详细泳道

时间顺序为 **AICPU RunWall 开始 → 首个计算核开始 → 末个计算核结束 → AICPU RunWall 结束**。前后两段包含 AICPU 工作与等待。使用同源、同纪元的设备计数器才能拆分；Host 时钟单独统计。

本轮使用适配分支的 **L3 + AICPU 生命周期细分**。打点沿用 `e4a3363` 的方法。表中数值来自本轮复测，每组预热 1 轮，取 10 个正式轮次的均值，单位为 µs。每轮按多个 AICPU 线程的时间区间取并集，父子阶段有包含关系。[原 AICPU 打点与拆解方法](https://github.com/mihudaner/simpler/blob/e4a336305fd8a289ef8fd876763c4067404a3a42/artifacts/26-11-17_aicore_cost_analyze/README.zh-CN.md)

A5 开启这套采集后，Device wall 为同批 L0 的 **3.16 倍**，AICore 窗口为 **1.55 倍**。其中约 442 µs 用于收尾时汇总采集记录。只保存了一份详细泳道，选 Device wall 最接近本组中位数的正式轮（run2，1180.953 µs），图中保留核名、依赖连线、AICPU 细分和上述三个时间段。下载后用 `xz -dk` 解压并打开 JSON。[A5 详细泳道](../results/swa-a5-hbg-L3-detail.json.xz)

**A6 已有观测。** `63cf2ab` 单卡输出检查通过。L4、零预热、1 轮，570 条执行和 570 条身份。设备首末核相差 997499 cycles（1 GHz），即 **997.499 µs**。转换器的 1032.11 µs 从下发算到完成，20.46 µs 是单执行实例平均计算时长，44.81 µs 是单实例从下发到完成的平均时长。它们分别保留作诊断。Host 时钟未对齐时，转换器在 Host 轨末尾拼接相对设备时间，图首约 166 ms 无法据此归到 Host 编排或设备 idle。原始 L4 的前三个 worker 正常结束，均报协议采集错误 4。已在 CPU 复现并修正 A6 的 MIX 确认记录越界。性能表只用 L0，带 AICPU 拆解的泳道只用 L3；L4 用于另行审计调度协议。
