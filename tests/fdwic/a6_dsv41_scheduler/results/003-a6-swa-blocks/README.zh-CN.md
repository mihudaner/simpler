# 阶段 003　A6 单卡 SWA 输出量化与输出投影分片

**与合并后原分片（002）相比，003 的 L0 核窗口从 328.139 降至 319.060 µs（−2.77%），Device wall 从 414.771 降至 406.690 µs（−1.95%）。30／30 个可写缓冲区通过。** 两个任务的 L3 表现方向相反：相对 00 的十轮均值，t17 缩短 32.385 µs，t20 增长 22.295 µs。002 缺少这两项的 L3 对照，暂不能把 t20 的增长全部归给改分片。

2026-11-20，提交 `f1ad55d`，Ascend960DT_966B7 逻辑设备 0，CANN 9.3.0。固定输入，生产 HBG，`--a6-plan quant54-oa54`，L0／L1／L3 各预热 1 轮、正式 10 轮。[复测方法](../../doc/a6-environment.zh-CN.md#已有性能数据的复测方法) · [指标 JSON](metrics.json)

## 改了什么

t17 输出量化把 64 个 tile 分给 54 个 V block，原先第二批的 10 个 tile 改由 10 个 block 在核内各多算一个。t20 O-A 把同样数量的 tile 从 32 组 1C1V 改分给 54 组，其中 44 组算一个、10 组算两个。每轮执行实例由 570 变为 604（t17 减 10，t20 增 44）。19 份核机器码和打包的 callable 一致，2735 条 plan 记录已逐项核对。t21 O-B 和 t27 HC post 在 003 仍各提交 32 个 C block 和 64 个 V block。

## 哪些变快，哪些回退

下表统一使用 **A6 L3 十轮均值**。每个任务取首个核实例开始到末个实例结束的跨度，包含同任务各 block 的启动间隔。

| 指标（µs） | 00 合并前原分片 | 003 合并后新分片 | 003 − 00 |
| ---------- | --------------: | ---------------: | -------: |
| t17 输出量化跨度 | 65.093 | 32.708 | **−32.385** |
| t20 O-A 投影跨度 | 39.725 | 62.020 | **+22.295** |
| AICore 窗口 | 666.058 | 634.772 | −31.286 |
| AICPU 计算前（其中 bootstrap 等待） | 177.689（58.366） | 176.810（46.192） | −0.879（−12.174） |
| AICPU 计算后（其中泳道汇总） | 355.150（263.699） | 370.105（288.007） | +14.955（**+24.308**） |
| Device wall | 1198.896 | 1181.688 | −17.208 |

**t20 扩组出现局部回退迹象**。32 组各算两块变为 54 组后，最忙的 10 组仍算两块，调度却多了 22 对 C/V。要区分分片和主线调度的影响，可在同一运行时对比 `quant54`（t20 用 32 组）和 `quant54-oa54`（54 组），两者 t17 都是 54。泳道汇总的增长出现在 L3 采集收尾，L0 的计算后段仅比 002 多 0.165 µs。

**L1 同步下界**为 207.210 µs，低于 00 的 212.200 µs，差 4.990 µs。按 54C／54V、604 个实际执行实例和十轮 L1 核时长求解，100 ns 向下量化，十轮均得到最优解。L0 核窗口高于该下界 53.98%（00 为 74.51%）。两次下界使用各自实测核时长，4.990 µs 无法单独分摊给 t17 和 t20。L3 代表轮是 run1（Device wall 1170.026 µs）；上表按十轮计算。逐轮下界及完整生命周期数值见[指标 JSON](metrics.json)。
